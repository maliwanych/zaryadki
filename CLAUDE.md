# Зарядки — учёт зарядок электромобиля

Инструкция для Claude Code. Отвечай по-русски, простыми словами. Git, GitHub Actions и публикацию владелец осваивает на этом проекте — объясняй, что и зачем делаешь, а не просто делай.

## Что это

Офлайн-приложение для телефона (PWA): зарядки, пробег, расходы на машину, напоминания о ТО. Считает стоимость километра, расход кВт·ч/100 км, экономию на бесплатных зарядках, реальный запас хода на полном заряде.

- Один файл `app/index.html` (HTML + CSS + JS без сборки и фреймворков) + `app/sw.js` (офлайн и обновления) + `app/manifest.webmanifest` + значки (`app/icons/`: рисуются из `design/icon-mark.svg` командой `npm run icons`, руками PNG не править; для iPhone — `apple-touch-icon.png` без прозрачных углов) + `app/privacy.html` (конфиденциальность; без внешних загрузок — проверяет тест). Если меняется, что приложение запрашивает из сети или как хранит данные, — обновить `privacy.html`.
- **Данные хранятся только на телефоне** (localStorage). Сервера нет, ничего никуда не отправляется. Это главное обещание пользователям — не нарушать.
- Публикация: GitHub Pages через GitHub Actions (`.github/workflows/deploy.yml`): push в `main` → тесты → публикация папки `app/`.
- Адрес: `https://<аккаунт>.github.io/zaryadki/`. **Не переименовывать репозиторий и аккаунт**: данные на телефонах привязаны к адресу, после переименования приложение у всех откроется пустым.
- Валюта BYN или ₽ (настройка `currency`; подписи — через `cur()` и `<span class="cur">`, не писать «BYN» в коде), интерфейс на русском, экран телефона ~400 px — проверять вёрстку на этой ширине.

История: приложение выросло из трекера, который владелец вёл как артефакт в Claude (там данные лежали в базе артефакта). Эта версия — публичная, без привязки к Claude и к чьим-то личным данным.

## Команды

```
npm install                 # один раз
npm start                   # открыть приложение: http://localhost:8765
npm test                    # автотесты Playwright (Chromium, экран телефона)
npx playwright install chromium   # если браузер для тестов не установлен
```

Перед каждым коммитом с изменениями в `app/` — `npm test`. Тесты идут по одному (`workers: 1`): тест обновления временно меняет `app/sw.js` и восстанавливает его.

На GitHub тесты идут в готовом контейнере Playwright (`deploy.yml` → `container.image`). При обновлении `@playwright/test` в `package.json` менять и версию контейнера, тест проверяет совпадение.

## Выпуск новой версии

1. Изменения в `app/`.
2. Поднять версию **в трёх местах одинаково**: `APP_VERSION` в `app/index.html`, `VERSION` в `app/sw.js`, `version` в `package.json`. Тест проверяет совпадение. Без смены `VERSION` в `sw.js` телефоны не узнают об обновлении.
3. Записать изменения в `CHANGELOG.md`.
4. `npm test` → коммит → push в `main`. GitHub Actions прогонит тесты и опубликует. У пользователей появится плашка «Доступна новая версия».
5. Если сломалось — `git revert` проблемного коммита и push (не переписывать историю `main`).

Крупные изменения — через ветку и pull request: на PR тесты запускаются, публикации нет.

## Устройство кода (app/index.html)

- `LocalDB(key)` — маленькое хранилище поверх localStorage с API как у Firestore: `db.doc("meta/settings").set()`, `db.collection("sessions").doc(id).set()`, `.onSnapshot()`. Первый снимок `onSnapshot` приходит сразу (синхронно), чтобы первая отрисовка уже была с данными; `S.configured` — `undefined`, пока настройки не прочитаны (приветствие показывается только при `false`). Ключ localStorage: `ev-tracker`, формат `{schema: 1, docs: {"коллекция/id": {...}}}`. Обработчики `onSnapshot` только обновляют `S`; `render()` вызывает `db.onChange(render)` — подписан последним, поэтому один раз на изменение, после всех обработчиков.
- Состояние в объекте `S`; при любом изменении — `render()` целиком. `computeStats()` — все основные расчёты.
- `saveFile()` — на телефоне меню «Поделиться» (Telegram, Диск, Файлы), иначе обычное скачивание.
- Импорт зарядок из Excel/CSV — `openTableImport()`: чтение `readXlsx()` (свой разбор zip, deflate через `DecompressionStream`) и `parseCsv()` (UTF-8 или Windows-1251), сопоставление колонок `XFIELDS` (угадывается по заголовкам, «Моя машина» и наша выгрузка — сами), строки → зарядки в `xRows()`, повторы по `sKey()` пропускаются, запись одним `db.setMany()`. Одна кнопка выбора файла: JSON — резервная копия (замена), zip/CSV — импорт (добавление). Отмена — общая с загрузкой копии (`rememberUndo()` / `offerUndo()`).
- Выгрузка в Excel — `buildXlsx()`: свой .xlsx без библиотек (zip без сжатия `zipStore()` + XML листов, строки inline, даты — числа Excel со стилем). Листы — `exportSheets()`.
- Подсказки станций — свой список `#stationSug` (`showStationSug()`), не `<datalist>`: в Edge на Android datalist не открывается, а над клавиатурой рисует пустые кружки.
- Открытое окно (`dialog[open]`) ставит `html.modal-open` — страница за ним не прокручивается, `overscroll-behavior` не даёт «потянуть, чтобы обновить» стереть форму.
- `registerSW()` — офлайн-режим и плашка обновления. Перезагрузка страницы **только** после нажатия «Обновить» (при первом визите worker тоже берёт управление — перезагрузка там стирала бы ввод).
- Вкладки: Обзор, Зарядки, Расходы, Напоминания (`data-tab` у секций, `setTab()`). Секция с `data-empty` скрыта, пока ей нечего показать (`showIf()`).
- «Обзор» сверху вниз: счётчик → цифры → итог и «Как это считается» (`notes` — в виду, `how` — под кнопкой) → пробег → точный расход и реальный запас (`#f2fSec`) → график по месяцам (`renderChart()`, чистый HTML/CSS, без библиотек; метрики — `CHART`) → две последние карточки месяцев и «Все месяцы».

## Модель данных

| Коллекция | Поля |
|---|---|
| `sessions/*` | `ts` (локальное "YYYY-MM-DDTHH:MM"), `station`, `kwh` (из сети, по счётчику станции), `byn`, `type`: `ac` / `dc` / `hwy` (трасса), `odo`, `socTo` (% после), `kwhBat` (сколько приняла машина, с её экрана), `socFrom` (устаревшее) |
| `fuel/*` | заправки гибрида: `ts`, `station` (АЗС), `liters`, `byn`, `odo`, `full` (полный бак) |
| `odo/*` | `date` (ISO), `odo`, `range` (запас хода с панели) — журнал замеров |
| `costs/*` | `byn`, `date`, `note`, `odo`, `kind`: `run` (текущий) / `period` (за `periodMonths` мес.) / `km` (на `lifeKm` км) / `invest` (разовое вложение, не входит в цену км) |
| `reminders/*` | `title`, `everyKm`, `lastOdo`, `dueDate`, `everyMonths`, `lastDate` |
| `refunds/*` | возвраты денег за поездки — в интерфейсе скрыты, сохраняются ради совместимости копий |
| `meta/settings` | `carName`, `purchaseDate` / `startOdo` / `startRange` — **начало учёта**: дата, пробег и запас хода в день, с которого записываются все зарядки (имена полей исторические, от «покупки»; не переименовывать — формат копий), `capKwh` (полезная ёмкость), `carCons`, `currency`: `BYN` / `RUB` (нет поля — BYN; поле `byn` в записях — просто сумма в выбранной валюте), `powertrain`: `phev` — гибрид с розеткой (нет поля или `ev` — электромобиль) |
| `meta/current` | последний замер пробега и запаса |
| `meta/backup` | дата последней резервной копии |

Отмена загрузки копии, импорта и «Удалить все данные» (`btnWipe`, удаляет через `db.replaceAll({})`): перед заменой прежнее содержимое `ev-tracker` (строкой, как есть) кладётся в ключ `ev-tracker-undo` вместе с датой загрузки (`{at, data}`) и лежит там до следующей загрузки. Миграция формата хранения должна переделывать и эту копию (или удалять её). Ключ `ev-tracker-ios-hint` = `"1"` — пользователь скрыл подсказку для iPhone. Ключ `ev-tracker-theme` = `light` / `dark` (нет ключа — как в телефоне) — тема из настроек, только на этом телефоне, в копию не входит; применяется скриптом `applyTheme()` в `<head>` до первой отрисовки (в `index.html` и `privacy.html`). Пример с данными (`demoDocs()`, генерируется от сегодняшней даты) живёт в ключе `ev-tracker-demo` (время входа — `ev-tracker-demo-at`, остатки старше суток удаляются при запуске), режим включает `sessionStorage["ev-tracker-demo"]` на время вкладки; в режиме примера настоящий ключ `ev-tracker` не читается и не пишется, копии и отмена загрузки недоступны.

Формат резервной копии (JSON): `{exportedAt, settings, current, sessions[], fuel[], odo[], refunds[], costs[], reminders[]}`, у элементов массивов есть `id`. **Этот формат нельзя ломать**: старые копии должны загружаться всегда. Если меняется формат хранения — писать миграцию, которая переделает данные на каждом телефоне при открытии (поле `schema` в localStorage).

## Ключевые расчёты (почему так)

- **Зарядка < 1 кВт·ч** = сбой старта (`glitch`), не учитывается в средних.
- **Бесплатная** = `byn === 0`. Экономия = кВт·ч бесплатных × средняя цена платных.
- **Цена и расход на 100 км** считаются по зарядкам не раньше начала учёта (более ранние — в «Потрачено», но не в цене км; пояснение под цифрами) на момент последнего замера с запасом хода (`Rr`): оплаченные км = (одометр − пробег в начале учёта) + запас сейчас − запас в начале учёта. Если оплаченные км ≤ 0 (сразу после начала учёта) — «—» и пояснение. В расчёт входят только зарядки «до» этого замера (`inBefore`): по одометру, а без него — по времени (+30 мин). Зарядки после — «не учтены, обновите пробег». Так цифры не прыгают при вводе новой зарядки.
- **Точный расход** — между двумя зарядками до 100% с одометром («от полного до полного»).
- **Реальный запас на полном заряде** = `capKwh` × км интервала / сумма `kwhBat` всех зарядок интервала. Только если у всех зарядок интервала есть `kwhBat` — приблизительные значения сюда не попадают.
- **Потери на зарядке** = `kwh / kwhBat − 1` (по зарядкам, где известны обе цифры).
- **Прочие расходы**: `period` раскладывается по месяцам (оплата вперёд), `km` — по км, пройденным после расхода (от его `odo` или пробега на его дату), `invest` в стоимость км не входит. Стоимость владения на 100 км = зарядки (на оплаченные км) + накопленные прочие (на пройденные км).
- **Гибрид с розеткой** (`HYB()`, `hybridStats()`): только зарядки и заправки и их деньги, данные машины (запас хода, ёмкость) не используются. Деньги на 100 км — «от полного бака до полного»: все заправки и зарядки после первой заправки «полный бак» с пробегом и до последней такой же, делённые на км между ними; иначе «≈» — все деньги с начала учёта на все км. «На 100 км пути» — залитые литры и кВт·ч на те же км (это не расход машины). Месяц — по пробегу за месяц, всегда «≈».
- **Месячная экономия** — бесплатные кВт·ч × средняя цена платных зарядок на конец этого месяца; так прошлые месяцы не меняются от новых зарядок. «Доли дешёвых» нет: что дёшево, каждый решает сам (решение владельца, 1.0.12).

## Правила

- Репозиторий **публичный**: никаких личных данных (реальные зарядки, адреса, имена, почта) — ни в коде, ни в тестах, ни в коммитах. Тестовые данные — только вымышленные (`tests/fixtures/sample-backup.json`). Резервные копии `*backup*.json` в `.gitignore`.
- Без внешних зависимостей в `app/`: приложение обращается только к своему адресу (проверяют тесты). Шрифт Onest лежит в `app/fonts/` (лицензия OFL, `OFL.txt` рядом). Никаких сборщиков — файл должен открываться как есть.
- Каждое изменение поведения — с тестом в `tests/app.spec.js`.
- Перед публикацией проверить на ширине 400 px и в тёмной теме.
